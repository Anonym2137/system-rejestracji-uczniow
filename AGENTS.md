# AGENTS.md — System Rejestracji Wyjść Uczniów

A Next.js 16 app for teachers to register student exits from lessons (toilet, nurse, etc.), track returns, and view history. Polish-language UI. Stack: Next.js 16 + React 19 + TypeScript + Tailwind v4 + Drizzle ORM + Better Auth + SQLite (libsql).

## Dev environment

```bash
npm install
cp .env.example .env   # fill in BETTER_AUTH_SECRET (min 32 chars)
npm run dev            # starts on http://localhost:3000
```

Required env vars (see `.env.example`):
- `DB_FILE_NAME` — path to SQLite file (default `./sqlite.db`)
- `BETTER_AUTH_SECRET` — min 32 chars, used for session signing
- `BETTER_AUTH_URL` — base URL (default `http://localhost:3000`)

## Build & test

```bash
npm run lint          # ESLint
npm run build         # production build
npm run start         # serve production build
npm run db:generate   # generate Drizzle migration from schema
npm run db:migrate    # apply migrations
npm run db:seed       # wipe + reseed dev database (destructive!)
```

No test suite exists. No CI config.

## Database

- Schema: `src/db/schema.ts` — tables: `user`, `session`, `account`, `verification` (Better Auth), `school_class`, `student`, `lesson_session`, `student_leave`, `audit_log`
- Migrations: `drizzle/` (generated by drizzle-kit, do not hand-edit)
- DB connection: `src/db/index.ts` uses `drizzle-orm/libsql` with `DB_FILE_NAME` env var
- Seed: `src/db/seed.ts` — creates 4 users (admin@gmail.com / haslo123, maria.w@szkola.pl, tomasz.n@szkola.pl, anna.n@szkola.pl), 2 classes, 5 students, 2 lessons, 2 leaves, 1 audit log entry. **Wipes all tables first.**

## Auth & roles

- Better Auth with email/password, configured in `src/lib/auth.ts`
- Roles: `admin`, `teacher`, `educator`, `student` (stored on user, default `teacher`)
- Middleware (`src/middleware.ts`) protects all routes except `/sign-in` and `/api/auth/*`
- API routes check session via `auth.api.getSession({ headers: await headers() })`
- Authorization pattern: teachers access only their own class (`educatorId` check); `admin` bypasses all ownership checks
- Client auth: `src/lib/auth-client.ts` exports `signIn`, `signOut`, `useSession`

## API routes

| Route | Method | Purpose |
|---|---|---|
| `/api/dashboard` | GET | Current class, active lesson, students, leaves, today stats |
| `/api/lesson` | POST | Start/stop lesson (`{action: "start"|"stop", classId?, lessonId?, subject?}`) |
| `/api/leaves` | POST | Register student exit (`{studentId, reason}`) |
| `/api/leaves/[id]/return` | PATCH | Register student return (writes `returnedAt` + audit log) |
| `/api/history` | GET | All leaves with filters: `?class=&reason=&from=&to=` |
| `/api/classes` | GET | Classes for current user (admin sees all) |
| `/api/students` | GET | Students by `?classId=` |
| `/api/auth/[...auth]` | * | Better Auth handler |

## Conventions

- All page components use `"use client"` directive
- API routes return `NextResponse.json(...)` with `{ error: string }` on failure
- Column names in DB are `snake_case`; Drizzle schema maps to camelCase TS fields
- Better Auth uses `mapFields` config to bridge camelCase ↔ snake_case
- Tailwind v4: no config file, uses `@import "tailwindcss"` in `globals.css`
- Path alias: `@/*` → `./*` (tsconfig)
- UI text is in Polish
- Fonts: Geist Sans + Geist Mono via `next/font/google`

## Project structure

```
src/
  app/
    (pages)/          # route group: dashboard, history, classes, settings, sign-in
    api/              # API routes (see table above)
    layout.tsx        # root layout
    globals.css       # Tailwind v4 entry
  db/
    schema.ts         # Drizzle schema (all tables)
    index.ts          # DB client instance
    seed.ts           # dev seeder
  lib/
    auth.ts           # Better Auth server config
    auth-client.ts    # Better Auth client (React hooks)
  middleware.ts       # auth guard
drizzle/              # generated migrations
```

## Pitfalls

- **No tests** — verify changes manually in the browser
- **`db:seed` is destructive** — deletes all rows in all tables before inserting
- **Classes, History, and Settings pages contain hardcoded mock data** (initialClasses, initialUsers, initialHistory arrays) — only Dashboard is fully wired to the API
- **No CI** — no automated checks on push
- **Next.js 16 + Turbopack** — dev mode uses Turbopack by default; some older Next.js docs may not apply
- **`better-auth/minimal`** is imported (not the full `better-auth` package) — check available exports before adding plugins
- **Middleware runs on `nodejs` runtime** — not edge-compatible
- **sqlite.db is committed** — the dev database file is in the repo root
